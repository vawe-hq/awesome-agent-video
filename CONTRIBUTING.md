# Contributing

Open one pull request per entry. Small pull requests are easy to review.

## What goes in

A tool, library, skill or guide that helps someone make video with code or with a coding agent.

Include it when all of these are true:

- It is public and the link opens.
- It does real work, not only a landing page. A repo, docs or a hosted product you can try.
- You can state one fact about it that is on its own page (a license, an input format, a count, a quote). Say which page.

Leave it out when the entry is a template pack, a stock-footage site, or a tool with no public page.

## Entry format

```
- [Name](https://example.com) - One line with a fact from the tool's own page.
```

- Put the entry in the right section, in alphabetical order by name.
- State the license if the page gives one.
- No superlatives and no ranking words. Say what the tool does.
- Use the same plain tone for your own project as for any other.
- If you are the author, say so in the pull request.

## In the pull request

Give the link to the page where you read the fact, and the date. One or two lines are enough.

## Fixing an entry

If a fact is out of date or a link is dead, open a pull request with the fix and the source. Dead links are removed.
